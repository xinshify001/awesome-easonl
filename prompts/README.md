# 提示词库

存那些**反复用过、确实稳定有效**的提示词。一次性的不收。

每条要有：用途、正文、为什么要这么写。

---

## 拆解一篇文章

**用途**：读完一篇长文，想快速判断值不值得存。

```text
读这篇文章，回答四件事：
1. 它真正提供的信息是什么，去掉修辞之后还剩什么
2. 哪些是可复用的方法，哪些只是一次性的案例
3. 作者有没有利益相关，立场可能在哪偏
4. 如果我只有 3 分钟，最该拿走的是哪一句

文章：<粘贴内容或链接>
```

**为什么这么写**：直接问「总结一下」只会得到一段更短的复述。逼它区分「方法」和「案例」、逼它指出立场，才能得到判断而不是摘要。

---

## 审判一段代码改动

**用途**：改动不小，自己看不出问题。

```text
这段改动有风险吗？按这个顺序检查：
1. 边界情况：空值、极值、并发
2. 失败路径：出错时会不会静默吞掉
3. 有没有把密钥、路径、环境依赖写死
4. 三个月后我自己还能看懂吗

只报真问题，不要为了凑数而提建议。

改动：<粘贴 diff>
```

**为什么这么写**：「只报真问题」这句是关键。不加这句，模型会礼貌地生成一堆无关痛痒的建议，等于没看。

---

## 制定一个学习计划

**用途**：想学一样东西，但不知道从哪下手。

```text
我想学 <主题>，目前水平是 <描述>，每周能投入 <小时>。

请给一个 8 周计划，要求：
1. 每周只给一个可验证的产出物，不要给「学习 XX 概念」这种没法验收的任务
2. 第 4 周安排一次小项目，把前四周的东西串起来
3. 明确写出每个阶段最容易放弃的点，以及卡住时该怎么办
```

**为什么这么写**：学习计划最容易烂尾在「目标不可验收」。强制每周一个产出物，进度才有真假之分。
